# Trending Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Count anonymous visits to places, and show the most visited places today, this week and this month at the top of the Atlas tab.

**Architecture:**
- A Cloudflare Worker (`worker/`) backed by a D1 database counts visits and answers top-10 queries.
- A pure, tested module `src/trending.mjs` holds the id rules, the client-side once-a-day memory and the fetch helpers. Both the Worker and the app use it.
- `main.js` starts the 5 s visit timer.
- `search.js` draws a "Trending" category, first in the Atlas.

**Tech Stack:** Cloudflare Workers + D1 (wrangler 4), Three.js app, esbuild, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-20-trending-design.md`

## Global Constraints
- **Endpoints:**
  - `POST /visit {id}` → 204; a bad id → 400
  - `GET /top?range=day|week|month` → `{places:[{id,n}]}`: at most 10, with n ≥ 3, over the last 24 h, 7 days or 30 days, cached for 5 minutes
- **Id shapes:** `^[a-z0-9]{1,24}$` | `^star:(\d{1,6})$` with the number < 109400 | `^con:[A-Za-z]{3}$` | `^new:[A-Za-z0-9 .+\-']{1,40}$`
- **CORS:** only `https://syntheticbuilder.github.io` and `http://localhost:*` / `http://127.0.0.1:*`.
- **Privacy:**
  - The dedupe key is HMAC-SHA-256(secret, day + IP + id), cut to 16 hex characters.
  - IPs are never stored or logged.
  - `seen` rows from earlier days and `counts` rows older than 31 days are deleted by a daily cron.
- **A visit:**
  - the flight ends on a non-free focus
  - no tour is running
  - the user has touched, clicked or pressed a key before
  - the focus is unchanged and there is no new flight for 5 s
  - not already sent today (localStorage `cosmo.visits`)
  - the opt-out is not set (localStorage `cosmo.countVisits` = '0')
  - `navigator.globalPrivacyControl` is not true
- **The app never waits on the counter:**
  - every request has a 4 s timeout
  - any failure hides the Trending category
  - nothing is fetched until the Atlas tab opens
- **Names:** only names the app already has (places, constellations, star index). Ids it can't name are dropped.
- **Layout:** phone first at 375×812, rows ≥ 44 px, no horizontal scroll.
- **Commits:** noreply author, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
- Hostile POST bodies (huge, not JSON, `__proto__`, ids of the wrong shape) → 400, nothing stored.
- The counter is down or slow → Atlas opens normally, with no Trending chip and no console errors.
- A star id before star names have loaded → the row waits for names, or is dropped; never "Star 123" made up.
- A tour flying through stops → no visits sent.
- Two quick flights (A then B within 5 s) → only B counts, and only after 5 s at B.

### Task 1: `src/trending.mjs` + tests
- `validId(id) → boolean` (shapes above).
- `RANGES = ['day','week','month']`, `rangeHours(range) → 24 | 168 | 720`.
- `visitMemory(storage, today) → { has(id), add(id) }`: keeps only today's ids. It never throws.
- `shouldCount({ id, free, touring, hadInput, optOut, gpc }) → boolean`.
- `fetchTop(base, range, fetchFn, timeoutMs=4000) → Promise<[{id,n}] | null>` and `sendVisit(base, id, fetchFn)`: they never throw, and drop malformed entries and ids that fail `validId`.
- `COUNTER_URL` constant (filled in at deploy time).
- Tests: id shapes (good and bad, including `star:109400`, `__proto__`); memory roll-over and broken storage; shouldCount cases; fetchTop with a bad JSON body, a non-array, a timeout and a 500.

### Task 2: Worker (`worker/src/index.js`, `worker/schema.sql`, `worker/wrangler.toml`) + tests
- Handles `/visit` and `/top` as above. It uses `validId` from `src/trending.mjs`.
- Body limit 200 bytes, plus OPTIONS preflight.
- `scheduled()` cleanup.
- Tests with a fake D1 (`tests/worker.test.mjs`): CORS allow and deny, a bad body → 400, dedupe on the same day, ranges, the n ≥ 3 filter, at most 10 results.

### Task 3: App wiring
- **main.js:**
  - visit timer on flight end, the `hadInput` flag, tour check
  - the `api.trending` object: `top(range)`, `available()`
  - Settings checkbox "Count my visits for Trending"
  - About line
- **search.js:** a "Trending" chip first in the Atlas (only when the first fetch succeeds), range chips Today · Week · Month, rows `<kind> · N visits` through `rowEl`, letters hidden, star names via `loadStars`, constellations via `loadExtras`.

### Task 4: Deploy and verify
- `wrangler d1 create`, apply the schema, `wrangler secret put SALT`, `wrangler deploy`. The owner picks the workers.dev subdomain.
- Set `COUNTER_URL`, build, and test locally at 375×812 against the real counter.
- README, PROGRESS, final review, commit. Push only on the owner's yes.
